# Mathematical foundations

Every formula this project rests on, in one place, with a pointer to the code that implements it.
Written for the authors and anyone joining the project: it assumes transformers, cross-entropy and
gradient-based discrete search, and assumes nothing about this repository.

Three threads run through it. **Collapse** is a dynamical system on a trajectory of models.
**Surrogates** approximate a point on that trajectory the attacker cannot observe. The **attack**
is a constrained discrete optimization whose feasibility is governed by a measurable scalar, the
security margin. The last two sections cover the poisoning line of work and a symbol table.

---

## 1. Setup and notation

A trajectory of models `M_0, M_1, ..., M_G` is produced by recursive training. `M_base` is the
pristine pretrained model the trajectory starts from.

| symbol | meaning |
|---|---|
| `M_base` | the pristine base model, never fine-tuned here |
| `M_g` | the checkpoint after `g` rounds of recursive training |
| `D_g` | the corpus generated by `M_g` |
| `theta_g` | the parameters of `M_g` |
| `l_M(x)` | the logit vector `M` assigns at context `x` |
| `p_M(.` \| `x)` | the next-token distribution, `softmax(l_M(x))` |
| `s` | the adversarial suffix, a token sequence |
| `w`, `r` | the wrong (insecure) and right (secure) reference implementations |
| `V`, `T` | vocabulary size, sampling temperature |

The **per-token cross-entropy** of a target string `y` under model `M`, given a prompt built with
suffix `s`, is the quantity every loss below is written in:

    CE_M(y | s)  =  (1 / |y|) * sum_t  -log p_M( y_t | prompt(s), y_<t )

It is a *mean* over the target's tokens, so `|y| * CE_M(y | s) = -log p_M(y | prompt(s))` is the
sequence log-likelihood under teacher forcing. Implemented in `TargetModel.target_losses`
([run_attack.py](../run_attack.py)).

## 2. The collapse process

### 2.1 The two recursions

Generation `g` trains on what generation `g-1` wrote. This is the **data recursion** and it is the
collapse mechanism:

    D_g  ~  M_g( . | instructions )          sampled at (T, top-p, top-k)
    M_{g+1}  =  finetune( init_g , D_g )

The **weight recursion** is a separate choice. By default `init_g = M_base`: each generation
trains a new adapter on the pristine base, the "replace" setting of the model-collapse literature,
so only the data recurs. With `--recursive_init`, the ablation, `init_g = M_g`, so one LoRA
adapter keeps being optimized and the number of optimizer steps applied to it grows linearly in
`g`; at a high real-data fraction those steps are mostly the same human rows again and again, a
memorisation route to degradation that self-training does not cause. The two produce different
curves from the same data, which is why both are in the artifact names (`_freshinit`,
`_recursive`). Every result measured before 2026-10-15 is on recursive lineages.

### 2.2 The data mixture

`--real_data_fraction` interpolates the training corpus between self-generated and human text while
holding the corpus *size* fixed, so the number of optimizer steps per generation is constant and the
collapse curve stays attributable to composition rather than to budget:

    corpus_g  =  (1 - f) * sample(D_{g-1})  +  f * sample(H)        f in [0, 1], g >= 0
    D_{-1}    ~  M_base( . | instructions )                          the base model's own corpus

`f = 0` is the pure replace regime. `f = 1` is the **non-collapsing control**: same generation count,
same seeds, same step count, no self-generated data at all, which is what separates "self-training
moved the model" from "iterated fine-tuning moved the model".

**Generation 0 is mixed like every other generation** (since 2026-10-22), with the pristine base
model's own samples `D_{-1}` standing in for a previous generation's corpus. This is what the threat
model needs: the attacker's one fine-tune `M_0` has to be one application of the *same* map
`M_{g+1} = finetune(M_base, corpus_g)` that produces the deployer's `M_1, M_2, ...`, because every
surrogate of section 3 extends the step `M_base -> M_0` by a factor `n` and reads it as `n`
collapse steps. A generation 0 trained on `H` alone — the rule before 2026-10-22, kept as the
`--human_generation_zero` ablation — makes that step a fine-tune on human code, and `n` of them is
not where the lineage goes. At `f = 0` generation 0 is pure self-distillation of the base; at
`f = 1` the two rules coincide. Implemented in `mix_real_data`
([run_baseline.py](../run_baseline.py)), the base corpus sampled once per root before the loop.

### 2.3 Why truncated sampling drives collapse

Sampling at temperature `T` with nucleus or top-k truncation is a **mode-sharpening** map on the
output distribution. The exact statement that matters is about a pair of tokens. At temperature `T`
the normalizer cancels in a ratio, so for any two tokens `a, b` at the same context:

    log p_T(a | x)  -  log p_T(b | x)   =   ( l_a(x) - l_b(x) ) / T                      (exact)

A log-odds gap is therefore scaled by exactly `1/T` per sampling step. Below `T = 1` that is
amplification. Retraining on those samples carries the sharpened distribution into the next
generation's weights, which is the mechanism section 7 models as a linear map in logit space.
Truncation (`top-p < 1`, `top-k` finite) compounds it by deleting the tail outright.

Note what this does *not* say: the sequence-level log-odds of two different strings does not scale
exactly by `1/T`, because the per-step normalizers no longer cancel between two different
continuations. Only the single-position decision scales exactly.

## 3. Surrogates for an unobserved generation

The threat model gives the attacker `M_base` and `M_0` only. Every surrogate below approximates
`M_n` from those two, by assuming the trajectory is locally a straight line and extending it by a
factor `n`.

### 3.1 Logit space: the tilt

    l_ex(x)  =  l_base(x)  +  n * ( l_0(x) - l_base(x) )

Computed in float32, **not clamped**. Softmax is shift invariant and is evaluated by subtracting the
row maximum, so a large logit cannot overflow; clamping to a fixed range would instead tie every
token above the ceiling and flatten everything below the floor, destroying exactly the ranking the
extrapolation produces. In distribution space this is an **exponential tilt**:

    p_ex(. | x)   ∝   p_base(. | x)^(1 - n)  *  p_0(. | x)^n

which is the same algebra as classifier-free guidance with guidance weight `n`. Two consequences
the project uses. It is differentiable in the input embeddings through both models, so the
adversarial search can optimize against it exactly as against a real checkpoint. And it is a
*distribution*, not a checkpoint, so nothing is trained to produce it.

`extrapolate_logits` ([utils/extrapolation.py](../utils/extrapolation.py)) is the single definition,
shared by the attack surrogate and the corpus generator so the two cannot drift.

### 3.2 Weight space: LoRA alpha scaling

The same first-order step taken in parameters rather than logits:

    theta_n  ≈  theta_base  +  n * ( theta_0 - theta_base )

A LoRA layer adds `(alpha / rank) * B A` to a frozen base weight, so the whole fine-tuning delta is
proportional to `alpha`. Since `M_0` is one fine-tuning step from `M_base`, scaling alpha by `n`
*is* the weight-space counterpart of the tilt, and it costs one model instead of two.
`build_scaled_adapter` ([utils/extrapolation.py](../utils/extrapolation.py)).

### 3.3 Data space: stacked truncation

Collapse is driven by each generation resampling its own truncated output, so `n` generations stack
`n` truncations. If one step keeps the top `p_1` of the probability mass, then

    p_n  =  p_1 ^ n

`p_1` is *fitted* to reproduce the real `M_0`, not chosen. The schedule saturates toward a point
mass as `n` grows, which is the degenerate fixed point the real process converges to; a schedule
linear in `n` would instead run off the end of the simplex. `surrogate_top_p`
([utils/extrapolation.py](../utils/extrapolation.py)).

This surrogate is a *corpus-level* object. Its teacher-forced cross-entropy is identical to the base
model's, because truncation changes sampling and not likelihood, so it cannot serve as a search
proxy; the attack rejects it explicitly.

### 3.4 Choosing the factor `n`

Three answers to one question, and they disagree, which is itself data.

**The indexing rule** `n = g + 1` names the generation but asserts nothing about fidelity.

**The capability probe** (`-sf auto`) walks a ladder of factors top down and takes the largest at
which the surrogate still solves a required fraction of the clean tasks. It scans rather than
bisects, because capability is not monotonic in `n`.

**The calibration** solves, per generation, for the factor whose tilted perplexity matches the real
checkpoint's, by false position in log-perplexity:

    find n(g)  such that   log PPL_ex( n(g) )  =  log PPL_real( g )

Fitted on held-out human data, because the attacker needs the surrogate placed where generation `g`
sits on data nobody trained on. Since the fit needs checkpoints the attacker does not have, a
one-parameter law is fitted through the measured points and used to extrapolate:

    n(g)  =  1  +  scale * ln(1 + g)

`calibrated_factor` ([utils/extrapolation.py](../utils/extrapolation.py)). Measured on this repo's
0.5B run the indexing rule and the calibration diverge by many orders of magnitude in perplexity,
which is why the law exists.

### 3.5 The factor the attack wants is solvable in closed form

Perplexity calibration places the surrogate where generation `g` sits as a language model. An
attack needs it to sit where generation `g` sits *at the security decision*, which is a different
quantity. That one is solvable rather than fittable.

Because the tilt is affine in the natural parameters and the partition functions cancel in a
difference of log-probabilities taken at **one** position, the surrogate's decision margin is
exactly affine in the factor:

    m(n)  =  (1 - n) * m_base  +  n * m_0

Two consequences, both available from two forward passes and before any search:

    boundary factor    n*  =  m_base / (m_base - m_0)
    usable at all      iff  m_0 - m_base  <  0

A non-negative slope means every increase of the factor drives the surrogate *further* toward the
secure sink, so no factor whatsoever makes it model that target as insecure. This is a guarantee
from the geometry rather than a heuristic. Measured on the 0.5B rdf 0.5 lineage at the pristine
model's decision point: fetch_user has `n* = 2.25`, load_config `n* = 4.58`, and the other three
targets are unusable, run_ping because its boundary lies behind the base model, which already
prefers the shell string.

Both anchors must be scored at the *same* prefix or the cancellation does not happen and the law
does not hold; `run_margin.py --sink` therefore evaluates every model at the pristine model's own
decision point. `run_attack.py --surrogate_factor sink` reads the resulting table.

### 3.6 The entropy-matched tilt

The factor `n` scales the *difference* of the two anchors, which sets the direction of travel but
cannot set sharpness independently: as `n` grows the tilt tends to a point mass on the argmax of
`p_0 / p_base` and its entropy falls to zero. The real lineage goes the other way; on the 0.5B run
the mean next-token entropy rises from 0.26 nats at the base model to 0.42 by generation 9. A tilt
large enough to model a late generation's direction is therefore far too sharp to model its
distribution, and this, not the direction, is the capability ceiling. A temperature restores the
missing degree of freedom.

With `l_n = l_base + n (l_0 - l_base)` and `H(beta; l)` the entropy of `softmax(beta * l)`:

    l~_n  =  beta* . l_n          where  H(beta*; l_n)  =  H(1; l_0)

so `tau = 1 / beta*` and the surrogate is `l_n / tau`. The target is the generation-0 anchor's
entropy at the same context under the same forbidden-token mask, which costs no extra forward pass.

* **Existence and uniqueness.** `dH/dbeta = -beta * Var_p(l) < 0` unless the row is constant, so
  `H` is strictly decreasing in `beta` from `log|S|` to 0 and the root is unique. It is found by
  bisection on `log beta` over `[-3 ln 10, 3 ln 10]`, 12 halvings (the temperature within 0.2%). Newton with that closed form was
  tried and rejected: the variance collapses where the tilt concentrates and the step diverges.
* **Rank preservation.** `beta*` is a positive scalar per row, so argmax and greedy decoding are
  unchanged; only the mass behind the ranking, which sampling and the loss see, changes.
* **Geometry.** Scaling the natural parameter moves along the e-geodesic from the uniform
  distribution through `p_n`. The two operations span the family `p ∝ p_base^a p_0^b` with
  `(a, b) = (beta (1 - n), beta n)`; the plain tilt is the slice `a + b = 1`, the matched tilt
  replaces it with the level set `H(p) = H(p_0)`. The factor chooses the ray, the temperature the
  point on it.
* **Affine law.** `m~(n) = beta*(n) . [(1 - n) m_base + n m_0]`, same sign as 3.5, so `n*` is
  unchanged and `-sf sink` composes with `-em` without re-solving.
* **Gradient.** `tau` is detached: the gradient flows through the division as through a
  normalization constant, so the factor owns the direction and the anchor fixes the sharpness.
* **Why the anchor's entropy.** It is what the attacker observes. Since the real entropy keeps
  rising past the anchor it is a floor rather than a match; extrapolating the target as well,
  `H* = H_base + n (H_0 - H_base)`, is a one-line change not made because the measured trajectory
  is not linear in `g`.

Measured at `n = 2.25` on the 0.5B rdf 0.5 lineage the plain tilt solves 1 of 5 clean tasks and the
matched tilt 4 of 5, at no measurable runtime cost. `entropy_matched_scale` and the `match_entropy`
flag of `extrapolate_logits` ([utils/extrapolation.py](../utils/extrapolation.py)); enabled with
`run_attack.py --entropy_match`.

## 4. The adversarial search

### 4.1 The objective

Let `c` be the model under attack (the real checkpoint, or a surrogate in transfer mode) and let
`H` be the **hold set**: the models that must keep writing the secure implementation. `H` is the
pristine baseline, plus the generation-0 anchor under `--hold_anchor`, so `|H|` is 1 by default
and 2 under that flag.

    L(s)  =  CE_c(w | s)                                                        (1) break
           + nu  * relu( m_t - ( CE_c(r | s) - CE_c(w | s) ) )                  (2) decide
           + lam * (1/|H|) * sum_{h in H}  relu( m - CE_h(w | s) )              (3) hold away
           + mu  * (1/|H|) * sum_{h in H}  CE_h(r | s)                          (4) hold toward

Term by term.

**(1)** drives the insecure implementation's likelihood up on the model under attack.

**(2)** is the term that matches the loss to the verdict. (1) falling says the insecure code got
*likelier*, not that it overtook the secure one, and with two models in `H` pulling the suffix back
toward the secure code a suffix can improve (1) indefinitely without ever flipping the answer. (2)
is a hinge on the target's own decision margin and goes slack once the insecure code leads by `m_t`
nats per token. `m_t = 0` disables it and recovers the previous objective.

**(3)** is a hinge, not gradient ascent: unbounded ascent on `CE_h(w)` diverges. It stops
contributing once a hold model is already `m` nats away from the insecure code.

**(4)** anchors the hold models on the secure implementation, so that "did not emit the insecure
string" cannot be satisfied by making them emit garbage instead.

**The `1/|H|` is load-bearing.** Summing instead of averaging doubles the pressure to hold the
moment the anchor is added, while the single break term stays as it is, so `lam`, `mu` and `m`
silently stop meaning what they were calibrated to mean. Measured on one cell at a fixed budget,
the summed objective reached a best total of 5.90 and found no hit where the averaged one hits at
3.39. `run_selective_attack.py` generalizes the same rule to an arbitrary hold group.

`ContrastiveGCG.objective` and `.combined_gradient` ([run_attack.py](../run_attack.py)).

### 4.1b The sink-conditional objective

Every cross-entropy above is a mean over the whole reference implementation, a hundred-odd tokens
of which two or three decide the verdict. Measured on the 0.5B rdf 0.5 lineage that mean fell from
about 3 to about 0.8 nats per token while the surrogate's own output was unclassifiable in 75 of
75 checks: the suffix had pushed the model off the task rather than across the decision.

Let `k` be the length of the shared token prefix of the two references, `r_k = r[k:k')` the
secure continuation and `w_k = w[k:k'')` the insecure one (the first differing span; a pure
insertion is extended by one shared token so both are non-empty). Define, for any model `M`,

    pref_M(s)   =  log p_M(w_k | s, prefix) - log p_M(r_k | s, prefix)     insecure preference, nats
    prefix_M(s) =  mean cross-entropy of the shared prefix under M          stay-on-task

Both spans are teacher-forced on the same prefix, so `pref` is a difference of log-probabilities at
one context: a decision margin, the quantity the classifier reads and the quantity
`run_margin.py --sink` measures. With `--sink_objective` the search minimizes

    L(s) =  zeta  . relu(m_s - pref_c(s))                       target prefers the insecure span
          + kappa . prefix_c(s)                                  and still writes the prefix
          + lambda / |H| . sum_h relu(m + pref_h(s))             each hold model prefers the secure span
          + mu     / |H| . sum_h CE_h(r | s)                     and keeps writing the secure code

Three properties. Under the logit surrogate `pref_c` is exactly affine in the factor, by the
argument of 3.5, so the per-target boundary `n*` is the natural factor to search at and
`--surrogate_factor sink` now moves the surrogate to each target's own root (plus
`--sink_offset`). A positive scalar on the logits, the entropy-matching temperature of 3.6, scales
`pref` without changing its sign. And `m_s` is in nats of a two-way log-odds, so it maps directly
onto the sampled verdict: at temperature `T` the insecure span wins the two-way race with
probability `sigmoid(m_s / T)`, which at `m_s = 2`, `T = 0.7` is about 95%.

The full-sequence means are still computed and recorded (`col_wrong` and friends), so
`--max_wrong_loss` keeps its meaning. `ContrastiveGCG._sink_objective` and `._sink_gradient`;
result files carry `_sinkobj`.

### 4.2 The discrete step

The suffix is represented as a one-hot matrix `X` in `{0,1}^(|s| x V)`, and the input embeddings are
`e = X E` for embedding matrix `E`. The loss is differentiable in `X`, giving

    g  =  grad_X L(s)        in  R^(|s| x V)

`g[i, v]` is a first-order estimate of the change in `L` from putting token `v` at position `i`.
One GCG step is then:

1. for each position `i`, take the `k` tokens with the most negative `g[i, :]` as candidates
   (implemented as the top-k of `-g`, with disallowed tokens set to `+inf` first so they can never
   be selected, which is how the non-ASCII and special-token constraints enter);
2. draw `B` candidate suffixes, each replacing `n_replace` positions uniformly from those sets;
3. discard candidates that do not survive a detokenize/retokenize round trip;
4. evaluate `L` **exactly** on all survivors and keep the argmin.

The gradient only proposes; the exact evaluation decides. The search is greedy coordinate descent
in this sense and never accepts a worse candidate. Steps 1 and 3 are `sample_ids_from_grad` and
`filter_ids` ([utils/gcg.py](../utils/gcg.py)).

Note that this makes the search itself **decoding-blind**: teacher-forced cross-entropy involves no
sampling, which is why the data-space surrogate of 3.3 is useless here and why the verdict of
section 5 has to be imposed separately.

## 5. The verdict

### 5.1 The hit rule

Let `status_M in {secure, insecure, unclassified}` be the static classification of what model `M`
emits for the adversarial prompt. A hit requires both of:

    status_c  = insecure        the model under attack writes the vulnerability
    status_b  = secure          the pristine baseline does not

and, under `--hold_anchor` only, a third condition:

    status_a  = secure          the attacker's own generation-0 model does not

**The default is the two-sided rule, and it follows from the threat model of section 1.** The
attacker holds the foundational model and one fine-tune of it. That generation-0 model is the
*instrument* the surrogate is built from, not a deployment the suffix has to spare: nobody runs
the attacker's own scratch model, so a suffix that also breaks it costs the claim nothing. The
third condition is the stricter, optional claim — that the suffix is specific to *later* collapse
rather than to any descendant of the base model — and it shrinks the feasible set, which is why it
is reported as its own family rather than folded in.

### 5.2 Sampled majority

Each model is decoded `k` times at the deployment settings and charged with the **majority** status,
ties resolved against the hit. If a single sample is insecure with probability `q`, the model is
charged insecure iff

    Binomial(k, q)  >  k / 2

so the sampled verdict is, to first order, a threshold at `q = 1/2`, where the greedy verdict is a
threshold on the argmax. **The two verdicts are two thresholds on one underlying quantity**, which
is the subject of section 6 and the reason the project measures that quantity directly.

### 5.3 Loss and survival

Under ancestral sampling the probability of emitting the target exactly is

    P( y )  =  exp( - |y| * CE(y) )

so a target of 40 tokens at `CE = 0.05` nats/token is emitted about 14% of the time per draw, and
at `CE = 0.02` about 45%. This is what `--max_wrong_loss` thresholds: it refuses to count a hit
until the insecure code is likely enough to survive being sampled, instead of accepting the first
argmax flip. Truncation raises these numbers, since mass deleted from the tail is redistributed.

## 6. The security margin

A decoding-independent scalar that both verdicts are thresholds on. Measured on the **clean** prompt
to characterize a model, and on the adversarial prompt to characterize a suffix.
`run_margin.py measure()`.

### 6.1 Three quantities

Let `k` be the first position at which the tokenizations of `r` and `w` diverge, with the shared
prefix teacher-forced.

**Decision margin**, the log-odds of the secure token over the insecure one at the branch point:

    dm_M  =  log p_M( r_k | prefix )  -  log p_M( w_k | prefix )

**Sequence margin**, the same at the level of whole implementations:

    sm_M  =  log p_M( r )  -  log p_M( w )   =   |w| * CE_M(w)  -  |r| * CE_M(r)

**Entropy**, the mean next-token entropy over the secure target's positions, which is a direct
read-out of the sharpening of section 2.3 and serves as the collapse-severity axis:

    S_M  =  (1/|r|) * sum_t  H( p_M( . | r_<t ) )

### 6.2 How the margins relate to the verdicts

Greedy decoding emits the secure token at the branch point iff it is the argmax, which requires
`dm_M > 0` but is not implied by it, since a third token may lead. The measurement records
`secure_is_argmax` separately for exactly this reason, and it is often false: the model phrases the
function differently from both references, in which case `dm` compares two tokens the model was
never going to write and `sm` is the quantity to read.

By the exact result of section 2.3, `dm` at temperature `T` is `dm / T`. So lowering the
temperature scales the decision margin up and makes a flip harder, and raising it scales toward
zero and makes the outcome a coin flip. This is the formal content of "exploitability is
decoding-conditional".

### 6.3 Headroom, and its limits

Headroom is a diagnostic for the **three-sided** rule (`--hold_anchor`), where the model under
attack must be *closer* to the insecure variant than the anchor it has to spare. Under the default
two-sided rule the comparison is against the pristine baseline instead, and the same formula
applies with `sm_{M_base}` in place of `sm_{M_0}`. Hence

    headroom(g, task)  =  sm_{M_0}(task)  -  sm_{M_g}(task)

Positive headroom means collapse has already moved the target in the attack's favour relative to
the model that must be held. Negative headroom means the search is asked to drag the target past a
model it must simultaneously spare.

**Headroom is a prior, not a predictor.** Measured on the rdf 0.5 lineage, the only cell that
produced hits was ranked last of its peers by both the sequence and the decision form. A clean-prompt
margin says where a model starts, not how far a suffix can move it; the quantity that would predict
success is a sensitivity, not a level. Use the ranking to report and to diagnose, not to filter.

### 6.4 The admissibility band

Two conditions must hold at once for a cell `(g, task)` to support the claim. The capability gate
requires `M_g` to write *secure* code unaided, and headroom requires `M_g` to be *closer to
insecure* than `M_0`. These pull in opposite directions, and their intersection is the real object
of study. Measured on the rdf 0.5 lineage over 45 cells: 14 pass the gate, 13 have positive
headroom, and 3 satisfy both. The clearest illustration is the OS-command-injection target, which
has the largest headroom at every generation and is inadmissible at every generation because the
model that must be spared already writes the vulnerability with no suffix at all.

## 7. The collapse map (poisoning)

The poisoning line models collapse as a map on a scalar **observable** rather than on weights. Let
`r_n` be the trigger-context payload rate at generation `n`: the fraction of answers to
trigger-bearing instructions that contain the payload. One generation resamples and retrains, which
by section 2.3 is near-linear in logit coordinates:

    logit( r_{n+1} )  =  a * logit( r_n )  +  b                                       (the map)

with `a` the sharpening slope. Section 2.3 predicts `a ≈ 1/T`, about 1.43 at `T = 0.7`, but `a` is
*measured*, never assumed. The map is affine, so it has a single fixed point

    L*  =  b / (1 - a)            r*  =  sigmoid( L* )

In the shifted coordinate `u_n = logit(r_n) - L*` the map is pure geometric growth, `u_n = a^n u_0`,
giving three closed forms:

    forecast        r_n   =  sigmoid( L* + a^n * ( logit(r_0) - L* ) )
    activation      n*    =  log( -L* / ( logit(r_0) - L* ) ) / log(a)
    required dose   r_0   =  sigmoid( L* * ( 1 - a^{-n*} ) )

where activation is the generation at which greedy decoding flips, i.e. `logit(r) = 0`.

**The fixed point is unstable iff `a > 1`**, and a dormant payload amplifies iff additionally
`r* < 0.5`, so that the initial rate sits on the growing side. When those fail, no generation-0 dose
arms the fuse and the tools return infeasible rather than a number. That is a finding about the
attack surface, not a tuning failure: the LoRA fine-tune damps the sharpening.

Implemented in [utils/collapse_map.py](../utils/collapse_map.py), derived in
[collapse_map_poison.md](collapse_map_poison.md).

The earlier gradient-matching variant optimizes poison content against the *weight* surrogate of
3.2. If a reference backdoor sits at `theta*`, then under `theta_k ≈ theta_base + k(theta_0 -
theta_base)` the generation-0 delta needed to arrive there at generation `k` is `dW_0 = dW* / k`,
and the poison text is searched to make the training gradient point at it, by minimizing
`-cos( grad_B L , B* )` with the LoRA basis frozen. See
[gradient_matching_poison.md](gradient_matching_poison.md). It assumes weight-space collapse, which
is not the regime this pipeline is in, which is why the data-space map above replaced it.

|---|---|---|
| `n` | surrogate extrapolation factor | `g + 1` |
| `f` | real-data fraction in the training mixture | 0 |
| `T`, `p`, `k` | sampling temperature, nucleus, top-k | 0.7, 0.8, 20 |
| `lam` | weight of the hold-away hinge | 1.0 |
| `mu` | weight of the hold-toward term | 0.5 |
| `m` | hold-away hinge margin | 3.0 |
| `nu`, `m_t` | weight and margin of the target-side hinge | 1.0, 0 (off) |
| `B`, `k_top` | GCG search width, gradient top-k | 256, 256 |
| `H` | hold set, `{baseline}` by default, `{baseline, anchor}` under `--hold_anchor` | `{baseline}` |
| `a`, `b`, `L*` | collapse-map slope, intercept, fixed point | measured |
| `r_n` | trigger-context payload rate at generation `n` | measured |
